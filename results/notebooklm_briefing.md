# NotebookLM 用プロンプト集（次の一手を相談する）

## 使い方
1. NotebookLM に「ソース」として `results/research_log.md` を読み込ませる
   （これまでの全実験結果が入っている）。必要なら関連論文PDFも追加。
2. 下のプロンプトを1つずつチャットに貼り付けて質問する。
3. 返ってきた回答をこのプロジェクトの実験計画に取り込む。

---

## 前提（最初にこれを貼って文脈を与える）

```
私はWebカメラ1台のリアルタイム視線推定を開発しています。MediaPipeで顔478ランドマーク＋虹彩を検出し、
7〜14次元の幾何特徴（虹彩の正規化位置、頭部姿勢pitch/yaw、両目間距離、眼開きEAR、虹彩径など）を作り、
キャリブレーション回帰で画面上の視線座標を推定します。深層学習の巨大モデルは使いません。
最近、「26万フレームの多姿勢データで学習したグローバルMLP」と「ユーザ個別キャリブのローカル回帰」を
頭部姿勢で滑らかに切り替えるハイブリッド手法で、横向き時の誤差を9.6cm→3.8cm（60%改善）できました。
残りの弱点は「頭を縦に傾けた時の垂直視線」で、Pitchと誤差の相関が最も強いです。
以降の質問に、具体的な実装手順・優先順位・トレードオフを添えて答えてください。
```

---

## プロンプト（1つずつ貼る）

**1.**
```
Zhang et al. 2015 の Data Normalization（仮想680mm正規化カメラへの再投影で頭部姿勢を正規化する手法）を、
今の solvePnP＋幾何正規化のパイプラインに導入する具体的な手順を、擬似コード付きで示してください。
それによって「頭を縦に傾けた時の垂直視線」の誤差がなぜ減るのか、理由も説明してください。
```

**2.**
```
虹彩の楕円フィッティング（画像上の虹彩輪郭の傾き・アスペクト比）から視線角を直接推定する3D眼球モデル手法は、
私のランドマークベース手法より横向き（大ヨー/ピッチ）に強いですか？
実装コスト、精度、頑健性のトレードオフを表で比較してください。
```

**3.**
```
「キャリブは正面でしか取れないが、使用中は頭を自由に動かす」という制約下で、
私の姿勢ゲート融合（頭部姿勢がキャリブ範囲から離れるほどグローバルモデルを信頼する）以外に、
理論的に優れたキャリブレーション手法を3つ挙げ、それぞれの数式と実装難易度を示してください。
特に、グローバルモデルを事前分布としたベイズ的キャリブレーションの具体案を出してください。
```

**4.**
```
Blenderで疑似眼球＋3D顔をレンダリングして正解ラベル付きの合成視線データを自作します。
sim-to-realギャップを最小化するために、ドメインランダム化すべき要素（照明・肌・カメラ位置・眼形状・眼鏡など）を
効果が大きい順にランク付けし、それぞれ何段階くらい振ればよいか具体的な数値の目安を示してください。
```

**5.**
```
合成データで事前学習し、実データ（GazeCaptureや自分のwebカメラログ）で微調整する場合の、
最適な学習戦略（凍結する層、学習率、データ混合比、段階的解凍の順序）を具体的に示してください。
合成:実データの比率はどのくらいが目安ですか？
```

**6.**
```
実webカメラでsolvePnPの頭部姿勢が不安定で、pitchが±90°にフリップする現象が起きています。
原因の候補と、それぞれの対策（PnPのフラグ変更、RANSAC、時間フィルタ、学習ベース頭部姿勢推定への置換）を、
費用対効果の高い順に並べて、最初に試すべきものを1つ推薦してください。
```

**7.**
```
私の手法の「頭部姿勢ロバスト性」を最も厳しく検証できる公開データセットはどれですか？
MPIIFaceGaze / ETH-XGaze / Gaze360 / EYEDIAP を、頭部姿勢の広さ・ラベル品質・入手しやすさで比較し、
最初に使うべき1つと、その具体的な評価プロトコルを提案してください。
```

---

## 補足
- 回答が返ってきたら、このプロジェクトでは `benchmarks/` の高速ハーネス
  （抽出済み特徴cacheでMediaPipe再実行なしに数秒でモデル実験可能）で即検証できます。
- 実装可能な提案が来たら、そのまま実験ループに投入します。
