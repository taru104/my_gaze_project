## 「webカメラでの視線推定は精度が出ない」は、わりと定説だった

MediaPipe を使えば顔の478点も虹彩も簡単に取れます。なので
「webカメラで視線を取る」記事自体はいくつもあります。VTuber、VRChatのフルトラ、
フェイストラッキングの比較。

でも **「画面のどの座標を見ているか」を実用精度で出す**ところまで到達した日本語記事が、
探した限り見つかりませんでした。

代わりに見つかったのが、[MediapipeによるアイトラッキングでUIの操作は可能か？](https://note.com/takataok/n/n026cf1a14103)
という記事です。MediaPipe で虹彩の位置を取って Unity の UI を操作しようとした検証で、
結論はこうでした。

> 画面中心でキャリブレーションしても、パーティクルが動き続ける
> 細かい操作は難しい
> 実用には projection transformation と、虹彩がもっと精細に写るカメラ構成が要る

これは失敗談ではなく、**正直で正確な報告**だと思います。自分も最初は同じ壁にぶつかりました。
虹彩の座標は取れているのに、画面座標に落とすと誤差が9cm近くあって、
どうやっても改善しない。

この記事は、**その壁の正体が何だったのか**という話です。

---

## 原因1: モデルではなく、特徴量が間違っていた

精度が9cmから動かないので、まずモデルを疑いました。線形回帰、多項式回帰、Ridge、
思いつくものを総当たりしました。結果は全部 **9.6〜10.0cm に張り付き**。

ここで気づいたのは、**単純なモデルほど成績が悪い**ということでした。
過学習が原因なら、モデルを単純にすれば良くなるはずです。逆になっている。
つまり**モデルの問題ではない**。

犯人は特徴量でした。虹彩の位置を、**画像の中心**を基準に正規化していたんです。

```python
cx, cy = w / 2.0, h / 2.0        # ← 画像の中心
X_feat = ((L_cx - cx) / L_diam + (R_cx - cx) / R_diam) / 2.0
```

虹彩の直径で割っているので距離不変にはなっています。でも基準点が画像の中心なので、
**顔を平行移動させただけで、視線が1ミリも動いていなくても値が変わる**。

実際に相関を測ってみました。

| 特徴量 | 顔の画面内位置との相関 | 正解の視線との相関 |
|---|---|---|
| 画像中心基準（旧） | **0.98** | 0.48 |
| 目頭・目尻基準（新） | 0.14 | **0.68** |

視線センサーのつもりが、**顔位置センサー**でした。

基準を目頭・目尻の中点に変えて、目の幅で正規化する。これだけで
**9cm → 1.4cm**。モデルは最初から悪くなかった。
**解くべき不変性を間違えていた**だけでした。

## 原因2: 数値と体感が食い違ったとき、どちらを信じるか

次に、目の周辺を切り出した画像パッチを特徴に足してみました。

結果は **わずかに悪化**（1.63cm → 2.07cm）。数値だけ見れば却下です。

ところが実際に使うと、明らかに**画像版の方が安定している**。カーソルが暴れない。
数値は負けているのに、体感は勝っている。

そこで両方のログを取って「何が違うのか」を測り直しました。犯人はこれでした。

| | 平均誤差 | **カーソルが画面外に飛んだ率** |
|---|---|---|
| 幾何のみ | 1.63cm | **11.9%** |
| 画像パッチあり | 2.07cm | **6.3%** |

**平均誤差という単一の指標は「たまに大暴走する」を評価できていなかった。**
実際の使い心地を殺していたのは平均ではなく、この暴走の方でした。

体感が正しかったので、画像版をデフォルトにしました。

## 原因3: そもそも、自分の評価指標がバグっていた

ここが一番きつい話です。

公開データセット（MPIIFaceGaze）で評価するとき、正規化した誤差をcmに直していました。

```python
err_cm = sqrt(dx_norm**2 + dy_norm**2) * 30.0   # 画面幅30cm
```

見つけられますか。**縦と横の両方に30を掛けています。**

実際の画面は 286.5 × **179.0** mm です。横は約30cmで合っていますが、**縦は18cm**。
つまり縦方向の誤差を **30/17.9 = 1.68倍に水増し**していました。

軸ごとに実サイズで換算し直したら、報告していた 4.21cm は実際には **3.19cm** でした。

幸い「実際より悪く見えていた」方向だったので、この指標で選んだ手法が間違っていた
わけではありません。でも**逆だったら、積み上げた判断が全部ひっくり返っていました**。

**誰も監査しない指標は、静かにあなたの信念を決めます。**

## 「度」で測って、ようやく他と比較できるようになった

cm は画面サイズに依存するので、論文と比較できません。そこで MPIIFaceGaze の
3D注釈とモニター位置情報を使って、予測した画面座標をカメラ座標系に逆投影し、
**視線ベクトルの角度誤差**を出しました。

（逆投影が正しいことは、正解の3D注視点を画面座標から再構成して
**0.0mm 一致**することで確認しています）

| プロトコル | 誤差 |
|---|---|
| 同一人物・較正あり | 3.19 cm / **3.65°** |
| **他人・較正ゼロ** | 4.19 cm / 6.24° |
| 他人・16サンプル較正 | 3.51 cm / **5.73°** |

比較対象を2つ置きます。

**1. 同種の公開OSS（EyeTrax）と同一条件で直接対決**
自分の実機ログ17セッションで、まったく同じデータ・同じ評価方法で比較しました。

| 手法 | 全体 | 正面 | 横向き30°+ |
|---|---|---|---|
| EyeTrax (486次元) | 8.17cm | 10.88cm | 6.68cm |
| **Tgaze (16次元)** | **4.71cm** | **5.81cm** | **5.76cm** |

**次元数は 486 → 16 に減っているのに、誤差は42%減りました。**
高次元にすると、少ないキャリブ点では過学習します。情報を凝縮した方が汎化する。

**2. 2026年の論文と同じ評価プロトコルで**
同じ土俵（ランドマークのみ・少数較正）の論文 EMC-Gaze が、
MPIIFaceGaze の leave-one-person-out・16サンプル較正で **8.82°** を報告しています。
こちらは同じプロトコルで **5.73°** でした。

ただし **「SOTAを超えた」とは書きません。**
論文側は自前データで学習したモデルを MPII に転移した可能性が記述から読み取れ、
その場合こちらの方が条件が有利です。評価フレーム数の一致も確認できていません。
言えるのは「**GPUなしの16次元線形モデルが、この水準に到達した**」までです。

## 効かなかった手法（たぶんここが一番役に立つ）

67回の実験のうち、大半は失敗です。主なものを挙げます。

**リンバス（虹彩の輪郭）楕円フィッティング**
放射状にレイを飛ばしてサブピクセル精度の勾配で虹彩の輪郭を取り、楕円を当てる。
古典的な手法で、MediaPipe の点より精密なはずでした。**負けました。**

理由が面白くて、MediaPipe の虹彩中心は目頭・目尻と **同じ位相で揺れる**（相関0.997）んです。
なので目頭基準で正規化した瞬間、揺れが**相殺**される。
毎フレーム独立に画像から測る楕円中心は、この「共通モード除去」の恩恵を受けられない。
**精密に測ることと、正規化後に安定していることは別物**でした。

**パッチの解像度を上げる**
24×16 → 48×32 で改善。48×32 → 96×64 で**平坦**。手作り特徴の天井です。
ここから先は CNN のような学習された表現が要る、というのが実測から出た結論でした。

**頭部姿勢の交互作用項・輻輳角**
前者は過学習、後者は定義上ゼロ情報なので当然変わらず。

## 実験設計を間違えて、結論を撤回した話

「クリックを正解データとして使う適応（タップ適応）が、むしろ精度を悪化させている」
という結果が出ました。数字もはっきりしていたので、そう報告しました。

そうしたら **「タップされる点は"厳しい点"なんだから、悪くなるのは当然。
逆にその点を加えたら厳しい状況では良くなるはず」** という指摘を受けました。

正しかったです。自分の実験は二重に間違っていました。

1. 「タップ」をセッション後半の**連続フレーム**で代用していた
   → ユーザは「うまく合っていない時」にクリックする。実挙動を再現していない
2. **全フレームの平均**で評価していた
   → 効くはずの「厳しい領域」の利得が、平均に薄められて消えていた

難易度で層別して測り直したところ、**厳しい条件では -23%** 改善していました。
しかもタップを一様に抽出すると -6.5% にしか効かない。
「**厳しい所から引くほど効く**」という機構と、きれいに整合しました。

結論は撤回しました。
