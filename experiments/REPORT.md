## 🌅 起床後まとめ（最初にこれを読んで）

**正直な結論**：全姿勢1cmは**物理限界で未達**でした。横向き30+は3.84cmが限界。webカメラ+mediapipeの解像度の壁で、3D gaze角(姿勢ロバスト)でも7°≈6cm、深層学習(appearance CNN)でも文献で4-6°。**1cm=視線1°は、この構成では届かない**。ここは誠実に。

**でも大きな収穫があった**：**16D特徴化で横向きが半減**。
| | 現行7D H1 | **16D Huber** |
|---|---|---|
| 横向き30+ | 7.82cm | **3.84cm** |
| 別日への汎化(クロスセッション) | 5.20cm | **3.87cm(過学習なし)** |

→ あなたの「1.4cmはデータ依存では？」の懸念、16Dなら別日でも3.87cmで**過学習していない**と実証できた。

**★実装推奨（起きたらやる価値あり）**：現行アプリの`H1`を**16D化**する。
- `rich16d.py`は既に16D計算済 → `features.py`で`feat16`(全16次元)を返し、`HuberCalibration`に渡すだけ。
- 横向き30+が7.82→3.84cmに半減。正面も点LOOで2.5cm。実装は軽い(次元非依存)。
- さらに詰めるなら「正面=H1(実機1.4cm) + 横向き=16D」の`HybridCalibration`(要実機検証、tau=15で30+3.26cm)。

**何が効いて何がダメだったか**：
- 効く=豊富特徴(虹彩径/アスペクト比/虹彩vert/EAR)×ロバスト線形(Huber)。3D gaze角は姿勢ロバスト。
- ダメ=非線形全般(MLP/GBM/poly2/交互作用/姿勢条件)は点ごとLOOで過学習。MPII直結合は座標系差で破綻。

**次の一手**：(a)16D化を実装して実機で試す(横向きが体感で改善するはず) (b)ハッカソンは16D-Huber(全姿勢3-4cm)を推すか、正面特化H1(1.4cm)+研究の見せ方で。1cmは深層学習(GPU)+大データの別プロジェクト。

## 実験4: 3D視線ベクトル幾何(MPII gaze角, person-independent)
抽出 11960フレーム/15人 (各人上限800)
### person-independent gaze角 angular error(度) 頭部yaw帯別
  全体 median=7.21°  (参考: 50cmで1度≈0.87cm)
  頭部yaw  0-10: median=7.32° (n=5568)
  頭部yaw 10-20: median=7.15° (n=4630)
  頭部yaw 20-30: median=6.86° (n=1564)
  頭部yaw 30-90: median=9.19° (n=198)
→ 頭部yawが増えても角度誤差が増えなければ3D gaze角は姿勢ロバスト。cm換算は距離依存だが
  1度≈0.87cm(50cm)なので、全体7.2°≈6.3cm相当。

(実験4 完了 3.0分)

### exp4結論: 3D gaze角は姿勢ロバスト(だが絶対1cmは届かない)
- gaze角 angular error は頭部yaw 0-30°で 6.9-7.3°と一定、30+でも9.2°=**姿勢ロバスト**(画面座標直接は横向きで崩壊)。
- but person-independent 7.2°≈6.3cm。**1°(1cm)はappearance CNN(MPII論文4-6°)でも困難=物理的限界**。
- 3D化の価値は「姿勢ロバスト性」であり「1cm精度」ではない。個人キャリブで個人オフセット補正すれば数cmまで。

## ═══════════ 7時間耐久研究 最終総括 ═══════════
### 結論1: 全姿勢1cmは今の手法では届かない(正直に)
- **16D画面座標直接(最良)**: 30+ 3.84cm / 正面2.5cm / 全体3.12cm。クロスセッション3.87cm=過学習なし。
- 3D gaze角: 姿勢ロバスト(横向き7°一定)だが絶対6cm。非線形(MLP/GBM/poly2/交互/姿勢条件)は全て過学習。
- **1cm(=視線1°)は7D/16D+線形でもappearance CNN(GPU)でも物理的に極めて困難**。webカメラ+mediapipeの解像度限界。
### 結論2: だが「16D化」で横向きが劇的改善(★実装推奨★)
| | 現行7D H1 | 16D Huber |
|---|---|---|
| 正面0-10 | 6.11(点LOO)/1.4(実機) | 2.5 |
| 横向き30+ | 7.82 | **3.84** |
| クロスセッション(別日) | 5.20 | **3.87(過学習なし)** |
- 現行アプリH1を16D化すれば横向き30+が **7.82→3.84cm に半減**。ユーザ懸念「1.4cmはデータ依存」も16Dで頑健と実証。
### ★ 実装推奨(起床後にやる価値)
1. **features.py**: feat7d(feat16[:7]) → **feat16 全16次元** を返す(rich16dは既に16D計算済、[:16]にするだけ)。
2. **calibration.py**: H1は虹彩4D+姿勢補正の構造。16Dなら Ridge/HuberCalibration(次元非依存)に16Dを渡すのが最速で30+3.84cm。
3. **理想ハイブリッド**: 正面=個人H1(1.4cm) + 横向き=16D Huber を姿勢ゲートでブレンド(次のexp6で検証)。
### 届かなかった限界(正直)
- 全姿勢1cm: 未達(30+ 3.84cmが限界)。物理的にwebカメラの解像度・mediapipe精度の壁。
- 深層学習(CNN 3D): GPU必須でハッカソン期間外。ETH-XGaze: 個人登録不可。→ 現実解は16D化+多姿勢データ。
